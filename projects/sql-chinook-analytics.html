SQL Business Analytics for a Digital Media Store

In plain terms

Which products sell best, which customers spend the most, and is performance trending up or down. These are the questions a sales or finance team asks every single month, and answering them well means being able to query the data directly instead of waiting on a static report. This project answers nine such questions against the Chinook sample database, a relational digital media store with customers, invoices, tracks, albums, artists, and employees, using the same query techniques (joins, subqueries, and window functions) that power revenue and customer reporting in any business.

This is a small, widely used public practice dataset (59 customers, 412 invoices), so the revenue figures are illustrative rather than business scale. The point is the query technique, which works the same way on a dataset of any size.

All 9 queries

  1. Revenue by country, using JOIN, GROUP BY, and aggregates
  2. Revenue by genre and percent of total, using a multi-table JOIN and scalar subquery
  3. Monthly revenue with cumulative running total, using SUM() OVER
  4. Top 10 customers by lifetime spend, ranked with RANK() OVER
  5. Sales performance by employee, using a 3-table JOIN
  6. Customer value segmentation, using a CTE with NTILE(4) OVER
  7. Year over year average order value, using a CTE with LAG() OVER
  8. Tracks purchased more than the store average, using a correlated subquery and HAVING
  9. A reusable view for downstream reporting tools, using CREATE VIEW

What this means for a business

These are the same query patterns behind most revenue and customer reporting: which segment is most valuable, whether performance is improving, and where the biggest opportunities are hiding in the data. A team that can write queries like these does not have to wait on a fixed report to answer a new question, they can just ask it directly.

Sample query

WITH customer_spend AS (
  SELECT c.CustomerId, SUM(i.Total) AS total_spend
  FROM Customer c JOIN Invoice i ON i.CustomerId = c.CustomerId
  GROUP BY c.CustomerId
),
tiered AS (
  SELECT *, NTILE(4) OVER (ORDER BY total_spend DESC) AS spend_quartile
  FROM customer_spend
)
SELECT spend_quartile, COUNT(*) AS customers, ROUND(SUM(total_spend),2) AS segment_revenue
FROM tiered GROUP BY spend_quartile ORDER BY spend_quartile;
