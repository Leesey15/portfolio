In plain terms

Every dashboard and report a business relies on is only as good as the data behind it. If the underlying data is messy, duplicated, or full of errors, even the best looking dashboard is telling the wrong story. This project builds that foundation from scratch: a well organized database that checks its own data for mistakes automatically, so the numbers feeding into every report and decision can actually be trusted.

It is built on a real university learning dataset of 32,593 students and over 11 million interaction records, and it covers everything a company would need to get its data in order: cleaning and organizing the data, designing a proper database, making it fast to query, building automatic quality checks, and keeping it secure, in 13 stages from start to finish.

A runnable demo script (afilearn_all_phases_demo.py) reproduces every stage live on a small sample in seconds, so the full pipeline can be verified without needing the 11.1 million row source dataset on hand.

Selected technical highlights

  • Schema design: 7 tables in 3NF, composite primary keys, foreign key constraints, and CHECK constraints enforcing valid gender, result, and score ranges at the database level, verified with an automated constraint rejection test (invalid foreign keys and out of range values are rejected automatically).
  • Query optimization: demonstrated with EXPLAIN QUERY PLAN, a composite index on the largest interaction table, and ANALYZE, reporting an 87 to 95 percent query time improvement on the full 10.6 million row table.
  • Data quality: six automated checks (null constraints, valid value sets, numeric range checks, referential integrity) run as part of the pipeline and reported as a pass or fail JSON summary.
  • Star schema warehouse: dim_student, dim_course, fact_student_assessment, enabling pass rate by course queries via the fact table, the same warehousing pattern used in the Power BI project on this site.
  • Big data processing: DuckDB used for MapReduce style aggregation, reporting 896,000 rows per second on the full dataset.
  • Security: role based access control (Admin, Analyst, Viewer) with tested permission boundaries, SHA-256 pseudonymisation for PII masking, and checksum verified backups.

What this means for a business

In practice, this is the groundwork a company needs before it can trust its own dashboards. A retailer with messy sales data, a bank with scattered customer records, or any team drowning in spreadsheets would need something like this first: one clean source of truth, checked automatically, that every report can be built on with confidence.
