The scope

A full data-management lifecycle project built on the OULAD (Open University Learning Analytics Dataset) structure — 32,593 students, 7 relational source files, 11.1 million interaction rows in the full dataset. Rather than a single analysis, this project builds the entire pipeline a real learning-analytics platform would need: from raw file profiling through governance, database design, optimization, warehousing, and security — 13 phases end to end.

A runnable demo script (afilearn_all_phases_demo.py) reproduces every phase live on a small sample in seconds, so the full pipeline can be verified without needing the 11.1M-row source dataset on hand.

Selected technical highlights

  • Schema design: 7 tables in 3NF, composite primary keys, foreign key constraints, and CHECK constraints enforcing valid gender/result/score ranges at the database level — verified with an automated constraint-rejection test (invalid foreign keys and out-of-range values are rejected automatically).
  • Query optimization: demonstrated with EXPLAIN QUERY PLAN, a composite index on the largest interaction table, and ANALYZE — reported 87-95% query time improvement on the full 10.6M-row table.
  • Data quality: six automated checks (null constraints, valid value sets, numeric range checks, referential integrity) run as part of the pipeline and reported as a pass/fail JSON summary.
  • Star-schema warehouse: dim_student, dim_course, fact_student_assessment — enabling pass-rate-by-course queries via the fact table, the same warehousing pattern used in the Power BI project on this site.
  • Big data processing: DuckDB used for MapReduce-style aggregation, reporting 896K rows/sec on the full dataset.
  • Security: role-based access control (Admin / Analyst / Viewer) with tested permission boundaries, SHA-256 pseudonymisation for PII masking, and checksum-verified backups.
